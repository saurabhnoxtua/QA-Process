Noxtua · QA Strategy

Where quality lives today,
and where it needs to live next.

Six automated journeys, a layered QA model already drafted by the team, and a maintenance phase arriving soon. This is what holds, what doesn't, and the order to fix it in.

01 verify first

The merge gate may not be a gate

Journeys are believed to block merges. Confluence says E2E is not a required check. Believing in a net that isn't wired up is worse than having none.

02 no R1 coverage

Tenant isolation is untested

Multi-tenant, per-tenant IdP, and no journey asserts tenant A cannot reach tenant B's documents. That's a confidentiality incident, not a bug.

03 cheapest win

No UX, a11y, or visual checks exist

With BSI work and public-sector customers, BITV 2.0 conformance is plausibly contractual. The suite that would host these checks already exists.

          Section 07

          The gap nobody is covering

          Accessibility

          Possibly contractual

          BSI work plus public-sector legal customers point at BITV 2.0 / EN 301 549 / WCAG 2.1 AA. If procurement asks for a VPAT and there's no evidence, that's a deal-blocker. Start: add axe-core to the journeys that already visit those states.

          Visual regression

          The value is in the render

          Citation markers, bento expansion, side-by-side viewer, editor pane, matrix columns. A CSS change breaks all of these without failing one functional assertion. 15–20 snapshots, nightly, mask the AI response body.

          UX states

          Chat Journey is the template

          It already tests empty-title block, over-long truncation, cancel-keeps-original, Enter-to-rename. That's real UX rigour. Apply it to the other five.
